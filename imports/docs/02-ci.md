# CI and import-graph enforcement

PathClerk runs ESLint import-graph rules in GitHub Actions on every PR. Committed
metrics snapshots and `saf-imports snapshot check` are **not** part of CI today.

## What runs today

From `.github/workflows/unit-tests.yaml`:

```bash
cd daemon && npx eslint -c eslint.import-graph.config.js .
```

## Fixing import-graph issues

### Import graph grew in a test file

1. Use `saf-imports why <test-file> <suspect-module>` to find the new path.
2. Prefer **removing** unnecessary imports (deep imports, slim harnesses) over accepting growth.
3. Optionally capture a local snapshot with `saf-imports snapshot generate` for before/after comparison.

### Exports pattern uncovered

Run locally when changing hybrid-pattern packages:

```bash
npm exec saf-imports exports check --package @pathclerk/daemon-db
npm exec saf-imports exports check --package @pathclerk/daemon-sdk
npm exec saf-imports exports check --package @pathclerk/daemon-service-common
npm exec saf-imports exports check --package @pathclerk/daemon-clients-common
npm exec saf-imports exports check --package @pathclerk/daemon-forms
```

1. Add a wildcard pattern or `exportsAliases` entry in `package.json` (see [05-scaffold.md](./05-scaffold.md)).
2. Internal files (`schema.ts`, `testing/` dirs) are excluded from coverage — do not export them.

### SPA shell budget (local)

Shell gzip JS can be compared with `saf-imports snapshot check` when a snapshot includes
`bundles`. Route-level page chunks are warn-only in check mode. See [06-spa-bundles.md](./06-spa-bundles.md).

## ESLint import-graph rules (`daemon/eslint.import-graph.config.js`)

Runs in CI as `npx eslint -c eslint.import-graph.config.js .` from `daemon/`.

| Scope | Rule | Intent |
| --- | --- | --- |
| All daemon `**/*.ts` | `no-restricted-imports` | Deep imports for `@pathclerk/daemon-service-common` and `@pathclerk/daemon-db` (see `eslint.daemon-*-imports.js`) |
| `service/http/routes/**/*.ts` | `no-restricted-syntax` | Ban root `DaemonServiceRequestBody` / `DaemonServiceResponseBody` identifiers — use `@pathclerk/daemon-spec/operations/<id>` types |
| `clients/**`, `service/sdk/**` | `no-restricted-imports` | Ban `@pathclerk/daemon-sdk` and `@pathclerk/daemon-clients-common` root barrels |
| Integration tests | overrides in `eslint.integration-mocks-imports.js` | Vendor SDK imports must use `*.mocks.ts` shims |

Type-only imports from `@pathclerk/daemon-spec` root (schemas, helpers) are allowed outside HTTP routes.
`DaemonService*Body` in Vue/client code may still use the spec root — route handlers are the primary enforcement surface.

## Local snapshots

Generate a metrics snapshot (test graphs, entry probes, optional timings/bundles):

```bash
npm exec saf-imports snapshot generate --out notes/import-graph/snapshot.json --skip-timings
npm exec saf-imports snapshot check --against notes/import-graph/snapshot.json
```

Configure probes and bundle targets in root `package.json` → `safImports.snapshot`.
